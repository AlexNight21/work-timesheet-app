# AGENTS.md

## Проект

`work-timesheet-app` — web UI для заполнения и выгрузки отчётов о работе за период.

Сотрудник выбирает временной промежуток и по каждому дню указывает проекты и конкретно
выполненную работу. Итог формируется в виде Excel-отчёта для менеджеров.

Подробные требования к функционалу будут дополняться по ходу работы.

## Стек

- Python (3.13+)
- FastAPI (веб-слой, REST API)
- uv (управление зависимостями и запуск: `uv add`, `uv run`)
- openpyxl (генерация Excel-отчётов)
- Jinja2 + нативные HTML/CSS/JS (минимальный фронтенд, одна страница)
- Хранение данных — txt-файлы, без БД

## Ограничения

- **Не работать с Git и GitHub.** Никаких `git add/commit/push`, веток, PR, работы с
  remote. Все изменения оставлять в рабочей директории — проверку, коммиты и пуш
  делает пользователь вручную.
- Не создавать файлы вне рабочей директории проекта.

## Правила работы

- Следовать существующей структуре и стилю, прежде чем вводить новые соглашения.
- Зависимости добавлять только через `uv add`; не редактировать `pyproject.toml`
  вручную и не использовать `pip`.
- `pyproject.toml` и `uv.lock` — источник истины по версиям зависимостей.
- Новые требования и договорённости, влияющие на архитектуру, фиксировать в этом файле.
- Если требование неясно или допускает несколько трактовок — спросить, а не угадывать.
- Секреты (токены, пароли, строки подключения) не коммитить и не хардкодить —
  только через переменные окружения / `.env` (`.env` в `.gitignore`).

## Команды

```bash
uv sync                          # установить зависимости
uv run app/main.py               # запуск приложения напрямую
uv run fastapi dev app/main.py   # запуск сервера в режиме разработки
uv add <package>                 # добавить зависимость
```

## Структура

```text
app/                     # backend
  main.py                # создание FastAPI-приложения, статика, главная страница
  config.py              # пути к данным и отчётам
  api/routes.py          # REST API: справочники, генерация и скачивание отчёта
  models/schemas.py      # Pydantic-модели запросов и валидация
  services/
    dictionaries.py      # txt-справочники (companies/employees/departments/managers/projects)
    period.py            # рабочие дни и разбиение периода по неделям
    report.py            # генерация Excel-отчёта с нуля через openpyxl
    translit.py          # транслитерация ФИО для имени файла

src/                     # frontend
  templates/index.html   # единственная страница приложения
  static/css/styles.css
  static/js/app.js

data/
  template/timesheet_template.xlsx   # образец отчёта (не используется генератором)
  storage/                           # txt-справочники (создаются при первом добавлении)
  reports/                           # сгенерированные xlsx-отчёты
```

## Данные и отчёт

- Справочники: `companies.txt`, `employees.txt`, `departments.txt`, `managers.txt`,
  `projects.txt` в `data/storage/`.
- Формат txt: UTF-8, одна запись на строку. Файлы создаются автоматически при первом
  добавлении значения; пустые файлы заранее не создаются.
- Данные и сгенерированные отчёты не коммитятся (см. `.gitignore`).
- Excel-отчёт генерируется с нуля средствами openpyxl; файл
  `data/template/timesheet_template.xlsx` используется только как визуальный
  образец и при генерации не требуется. Недельные блоки формируются только по
  рабочим дням (пн-пт) в пределах выбранного периода.
- По умолчанию выходные в отчёт не попадают. Для каждой недели в UI можно
  дополнительно включить субботу и/или воскресенье как рабочие дни.
- Обед берётся из полей UI (по умолчанию 1 час, как в образце). В день можно указать
  несколько проектов; в отчёте они нумеруются и разделяются символом `;`.
- Для дня можно отметить отсутствие (плановый отпуск, отпуск за свой счёт,
  больничный, праздничный день или своя причина). В отчёте причина выводится в
  объединённых ячейках D:H без времени и проекта.
- Имя файла: `TimeSheet_<ФамилияИО>_<ддммгг>-<ддммгг>.xlsx`, ФИО транслитерируется.
